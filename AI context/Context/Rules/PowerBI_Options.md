# Power BI Desktop options — rules (all projects)

Settings every Power BI file must have. Check them when a project is opened for the
first time, and fix them as part of the work (user decision 2026-10-14).

| Option | Required | Where in Desktop | How to check in PBIP |

## ⚠️ Changing options requires a Desktop restart

An options change takes effect only after Power BI Desktop is restarted. Because of
the rule "never close the user's Desktop" (`PBIP_Model_Live.md`), **the user
changes the options and restarts Desktop themselves**. Claude only reports which
option is wrong and where to switch it, and does not close Desktop to apply it.
Even when the user asks Claude to restart, closing Desktop is blocked by the
Claude Code permission classifier (2026-10-14) — the user closes/reopens it.
Claude may change the option itself in the Options dialog (UI clicks) and save.
Plan option changes for the end of a work session (save first, Ctrl+S).

## Why

- **Auto date/time** creates a hidden date table for every date column: a bigger
  model, slower refresh, and a second, inconsistent calendar next to the project's
  own `Date` / `Calendar` table.
- **Q&A** builds and keeps a linguistic schema (`cultures/<culture>.tmdl`,
  `linguisticMetadata`) that nobody uses. It goes stale on every rename (ClientB
  2026-10-14: after renaming a Field Parameter via TOM the en-US bindings still
  pointed to the old names). **Desktop 2.158 regenerates the en-US schema on every save, Q&A on or off**
  (ClientB 2026-10-15 / 18: removed via TOM and from the file, back after the next save) — so it is left as is
  and never removed (user 2026-11-03: no rules for what Desktop regenerates).
