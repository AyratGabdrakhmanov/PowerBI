## Common problems and solutions

| Problem | Cause | Solution |
|----------|---------|---------|
| Page not visible in Power BI (no error) | A space in the page folder name, or a name mismatch across the three places | Remove spaces from the folder name, synchronize all three places |
| BOM error when opening the project | pages.json/page.json saved with a BOM | Re-save as UTF-8 without BOM (`System.Text.UTF8Encoding($false)`) |
| Only some pages are visible (for example, 3 out of 10) | Pages with spaces in the folder name are not found by Power BI | Remove spaces from all page folder names |
| After renaming a folder, the page disappeared | `page.json "name"` and `pages.json` were not updated to the new name | Synchronize both files with the new folder name |
| JSON looks "shifted" (floating indent) | `ConvertTo-Json` in Windows PowerShell 5.1 formats with indents that are not multiples of 2/4 spaces | Run the script under PowerShell 7+ (`pwsh`) — there the indent is always a clean 2 spaces per level |
| One of the renamed folders "got lost" | Collision: two `displayName` values coincided after removing spaces | Add a numeric suffix to the repeated name |
| The script "did not work" on double-click | Windows does not run `.ps1` on double-click / the window closes instantly | Run from cmd: `powershell -ExecutionPolicy Bypass -File script.ps1` |
| A rounded number was saved as `497.0`, not `497` | `[Math]::Round()` returns a `Double`, `ConvertTo-Json` writes `.0` even for whole Doubles | Explicitly cast to `[long]` before serialization |
| Cross-filtering between visuals stopped working after renaming a visual folder | `visualInteractions.source/target` in `page.json`, referencing the old folder ID, were not updated | Synchronize these references together with renaming the visual folder |
| A visual with a Style preset looks "almost like the reference, but not exactly" | The preset covers only `objects` (the inner look), while `border`/`background`/`padding` come from the global `visualStyles.*.*`, which differs from the reference | Add the container properties (`border`, `background`, `padding`, `visualLink`, etc.) to the named preset too |
| Need to reference `dataColors[N]` inside the theme, but the JSON fails validation | For `border.color`/`background.color` (`colorOrThemeColor`), indexing into `dataColors` is not supported | Use `ThemeDataColor` only where the property is of `fill` type (`fontColor`, `lineColor`, `fillColor`) |
| Renamed a layer in the Selection pane — can't figure out where it is stored | It is `visualContainerObjects.title.text`, not `general.altText` and not a separate "layer name" field | Look for/change `title.text` in `visual.json` |
| Promoted the `hover`/`selected` state to the base `"*"`, but the visual on the preset still has the wrong color/font | A preset, if it mentions a property at all (`fill`/`outline`/`text`...), fully replaces the base's whole array for that property — partial inheritance by `$id` does not work | Each preset must contain ALL the needed states itself, without relying on the base; only properties the preset does not mention at all can be promoted to the base |
| A chain of folder renames partially fails ("! Folder already exists") | The target name coincided with the name of a not-yet-processed folder during sequential `Rename-Item` | Use a two-phase rename: first all the relevant folders → unique temporary names, then → final names |
| Trimmed `dataColors`, some visuals started to look wrong (unfamiliar color) | A `ThemeDataColor.ColorId` reference points to an index that no longer exists in the shortened array | Before trimming the palette, grep all `"ColorId"` across the project and the theme |
| A real page with a unique `displayName` gets a suffix every time (`Details12` instead of `Details1`) | An orphaned folder without `page.json` has taken the short name and blocks it | Delete the orphan folder (after checking that its content is outdated/duplicated), rerun `rename_pages.ps1` |
| Theme validation fails: `Must match one of the following enum values: "left", "center", "right"` | `layout.alignment` inside `visualStyles` does not support `"middle"`, only `left`/`center`/`right` | Replace `"middle"` with `"center"` |
| A percentage measure's change shows `0.0`, although the actual change is noticeable | In `FORMAT()` without a `%` character in the format string, the number is not automatically multiplied by 100 | Explicitly multiply by 100 in DAX: `FORMAT(__MOM * 100, "...")` |
| A negative change shows the number without a minus sign | In a custom format with an explicitly defined negative section, the minus is not added automatically | Write `-` in the negative section of the format itself (`"-#,0.0 pp"`) |
| Special characters (`#`, `%`, `.`) remain in a visual/page folder name | The old script logic removed only spaces (`-replace '\s', ''`) | Use `Get-SafeName` (keeps only letters/digits) instead of `-replace '\s', ''` |
| A "Page navigation" button leads nowhere (silently does not work) | `navigationSection` references an old/non-existent page name — the script historically did not track this field when renaming | If the reference was still current at the time of the bug — update via the script (already fixed); if the mapping is lost — re-select the page manually in Power BI Desktop (Format → Action → Page navigation) |
| A button with the "Drillthrough" action — the Destination field in the Action pane is empty, although `navigationSection` next to it looks fine | `drillthroughSection` (not `navigationSection`) references an old/non-existent page name — the script historically did not track this particular field when renaming (fixed 2026-09-15) | If the reference was still current at the time of the bug — update via the script; if the mapping is lost — re-select the Destination manually in Power BI Desktop (Format → Action → Drillthrough), going by the button label and by which pages' `page.json` actually contains `"pageBinding": {"type": "Drillthrough"}` — see "⚠️⚠️ Three fields reference a PAGE..." |
| Publish / Export → Power BI Template fails: `Part URI is not valid per rules defined in the Open Packaging Conventions specification.` | The page/visual folder name (or its `"name"`) contains non-ASCII characters (Hebrew, Cyrillic, etc.) | Run `rename_pages.ps1` (now ASCII-only) or, for an existing project with non-ASCII names, run `fix_nonascii_names.ps1` once — see the section "⚠️⚠️ Non-ASCII folder name..." |
| After mass renaming, a visual "fell out" of its group / is visually in the wrong place in the tree | Loop-based (not single-pass) replacement of `parentGroupName` by the rename map — "chained substitution" overwrites someone else's reference if the old/new generic names overlap | Single-pass `[regex]::Replace` with `MatchEvaluator` (already fixed in the script) + reconciliation against the backup via title-based/tabOrder matching — see "⚠️⚠️ `parentGroupName`..." |
| A bookmark toggles `isHidden`, but there is no visible effect | `position.z` was compared in the wrong context (it is a local stack WITHIN the parent group, not across the whole page), or the toggled node itself (or one of its ancestors) is nested in the wrong group | Compare the entire `parentGroupName` chain of the toggled node against the backup, not only the z of the node itself — see "⚠️ Bookmarks and group visibility..." |
| Part of a bookmark's content (`visualContainers`/filters) silently disappeared after saving in Power BI Desktop | Officially documented behavior: Desktop itself cuts out of the bookmark any reference to a visual that has become invalid (for example, due to an unnoticed renaming breakage) on the next save in the UI — without an error | Check and fix all references in `bookmarks/*.bookmark.json` RIGHT AFTER renaming, before opening in Desktop — see "⚠️⚠️ Official MS documentation: renaming risks..." |
